# GridSight Congestion & Violation Intelligence Platform

GridSight is a scalable, AI-driven parking violation and traffic congestion impact management platform. It uses a **Next.js** frontend dashboard connected to a **Python FastAPI** backend running on top of **MongoDB** with real-time **Machine Learning** models.

---

## 🚀 Running the Project

To run GridSight end-to-end, you must start both the backend ML services and the Next.js frontend application.

### 1. Start the Backend (FastAPI ML Service)
The backend resides in `gridsight-services/ml-service`. It runs on port `8000` and connects to MongoDB.

1. Navigate to the service folder:
   ```bash
   cd gridsight-services/ml-service
   ```
2. Activate your virtual environment (if using one) and make sure dependencies are installed:
   ```bash
   pip install -r requirements.txt
   ```
3. Start the Uvicorn development server:
   ```bash
   python -m app.main
   ```
   *The Swagger API documentation will be available at [http://localhost:8000/docs](http://localhost:8000/docs).*

### 2. Start the Frontend (Next.js Application)
The frontend dashboard resides in `gridsight-app`. It runs on port `3000`.

1. Navigate to the app folder:
   ```bash
   cd gridsight-app
   ```
2. Install node dependencies:
   ```bash
   npm install
   ```
3. Start the Next.js development server:
   ```bash
   npm run dev
   ```
4. Open [http://localhost:3000](http://localhost:3000) in your web browser.

## 🗺️ Page Integration Guide

The following views in the Next.js application are connected to the live FastAPI backend:

### 1. Police Intake & Case Manager (`/police`)
*   **Intake & Search**: The cases list query parameters (`searchQuery`, `selectedStation`, etc.) are debounced (300ms) and mapped directly to dynamic MongoDB searches (`/api/violations/search`) running over **298,450 records**.
*   **Validation Updates**: Marking cases as Approved, Rejected, or Duplicate triggers a POST request to `/api/violations/{id}/validate`, updating the record state in MongoDB instantly.
*   **Offenders Registry**: Shows repeat offenders scored dynamically via a high-performance MongoDB aggregation pipeline (`/api/violations/repeat-offenders`).
*   **Device Productivity**: Live aggregates device capture counts and approval metrics (`/api/violations/device-productivity`).

### 2. Citizen Safety Advisory Portal (`/citizen`)
*   **Case Status Lookup**: Enter a license plate (e.g. `KA04...`) to search the full MongoDB database and return validation status updates.
*   **Advisory Hotspots**: Pulls hotspots representing density clusters dynamically.

## 🔮 Dynamic ML & Geospatial Behaviors

### 📍 Map Markers (DBSCAN Clusters)
Instead of hardcoded coordinates or random markers, both dashboards render markers representing **mathematically accurate centroids** of violation density.
*   The map fetches cluster data from `/api/ml/hotspots` (generated by **DBSCAN** spatial clustering).
*   The marker sizes and colors represent cluster density and average delay impact.
*   As tickets are approved or rejected, the open caseload changes, causing the **Priority Urgency Score** and **Enforcement Priority List** (generated by `/api/ml/enforcement-priorities`) to update dynamically.

### ⚡ Live Congestion Impact (Random Forest Inference)
In the Police Case Explorer, selecting any single violation card renders a **Live ML Traffic Congestion Impact** panel.
*   A POST request is sent to `/api/ml/predict-impact` with case parameters (coordinates, hour of day, vehicle size, violation type).
*   The backend loads `congestion_model.pkl` to run inference using the trained **Random Forest Regressor**.
*   The card displays:
    1.  **Congestion Score**: Scaled delay impact percentage.
    2.  **Predicted Delay**: Expected traffic queue delay in minutes.
    3.  **Estimated Speed Drop**: Estimated speed reduction in km/h.
    4.  **Action Recommendation**: Targeted dispatch instructions (e.g., *Deploy Tow Truck* for high-impact blocking).
